# cr-copy-deck · 皇室战争卡组一键导入

在电脑/手机浏览器里选一套卡组 → 扫码或点按钮 → 卡组直接导入手机上的《皇室战争》。

## 原理（它是怎么实现的）

你贴的那条真实链接：

```
clashroyale://copyDeck?deck=27000002;26000023;...;28000015&l=Royals&tt=159000000
```

- `clashroyale://` 是《皇室战争》App 注册的**自定义 URL scheme**（深链）。
- RoyaleAPI / Clashest 等网站上的 “复制卡组” 按钮，本质就是一个普通的
  `<a href="clashroyale://copyDeck?deck=...">` 链接。安卓点它时，系统把这个 URI 交给已安装的游戏。
- `link.clashroyale.com` 官方跳转页做的事（从其前端源码确认）只有两件：
  1. 把整段 `clashroyale://...` 原样作为按钮的 href；
  2. 桌面端额外画一个二维码，内容是当前 HTTPS 网址，方便手机扫码。
- 游戏收到 URI 后解析 `deck=` 里的 8 个卡牌 ID，在游戏内提示载入到卡组槽位。
- 参数：`deck` = 8 个卡牌 ID（`;` 分隔）；`l=Royals`、`tt=159000000` 为官方/第三方通用的固定字段。
- **形态（觉醒 / 英雄 / 精英）**：链接里用 `slots=` 表达，它与 `deck` **逐位对应**，
  已验证的写法是 `1 = 觉醒`、`0 = 普通`（例如 `&slots=1;0;0;0;0;0;0;0`）。
  英雄 / 精英的编码目前没有公开资料，本工具默认不写入（可在设置里填）。

也就是说：不需要逆向游戏，按同样格式拼链接即可。本工具就是把这件事做成页面。

## 使用方法

### 方式 A：电脑上打开（推荐）

1. 双击 `index.html`（或 `python3 -m http.server 8000` 后访问 http://localhost:8000）。
2. 点开一套卡组 → 用**手机相机扫页面上的二维码** → 打开官方页面 → 点 “Copy the deck” → 游戏自动载入。
3. 也可以点「复制导入链接」，把链接发到手机（微信/QQ/备忘录），在手机上点开。

### 方式 B：手机上直接打开

- 把 `index.html` 拷到手机用浏览器打开；或电脑上 `python3 -m http.server 8000`，
  手机浏览器访问 `http://<电脑局域网IP>:8000`（如 `http://192.168.1.5:8000`）。
- 点开卡组 → 点「在手机上导入」→ 直接跳到游戏。
- 建议用 http 方式打开：`file://` 下部分浏览器不允许保存卡组与设置（页面会提示）。

## 管理卡组

每张卡组卡片右上角常驻 **编辑 / 删除** 按钮。

### 添加 / 编辑卡组：8 个格子（每行 4 个，小尺寸）

格子里用**星标**表示形态，顺序固定为 **紫 → 橙 → 银**（银星永远在最后）：

| 星标 | 含义 | 能放的格子 |
|---|---|---|
| ★ 紫色 | 觉醒 | 第 1、3 格 |
| ★ 橙色 | 精英 / 英雄 | 第 2、3 格 |
| ★ 银色 | 普通 | **每一格都能放**（永远显示） |

例如：第 1 格 = `紫 银`，第 2 格 = `橙 银`，第 3 格 = `紫 橙 银`，第 4–8 格 = `银`。

- 卡片放进格子后，星标就是可点的切换按钮：点亮 = 当前形态；默认是银星（普通）；每个格子**只显示该格能用的形态**；
- 只有该卡真正拥有的星标才会出现（火球只有银星；英雄卡只有一颗橙星）；
- **清空格子**：再点一次格子里的卡（缩略图）即可清空，没有删除键；也可以再点下方卡牌列表里的同一张卡；
- `◀ ▶` 左右移动；把英雄卡往第 1 格或第 4–8 格移 → `⛔ 无法移动`；
- **放不了的卡直接拒绝**：`⛔ 无法加入：Archer Queen 只能放在第 2、3 格`，卡片不会被加入；
- 保存需要 8 格填满。

### 塔防（塔楼部队）

8 个格子**右侧**有一个稍大的**塔防槽**，用来保存塔楼部队（公主塔 / 炮塔 / 匕首公爵夫人 / 皇家厨师），
格子下方的下拉可以直接切换。

- 链接里的 `tt=` 参数就是塔楼部队 ID（`tt=159000000` = 公主塔），所以**导入/导出都带塔**：
  - 生成的链接会写入 `&tt=<所选塔>`；
  - 粘贴别人的复制卡组链接时，`tt=` 里的塔会自动带出来。
- 卡组卡片右侧也会显示该卡组的塔；详情里显示「塔防：xxx（tt=…）」。
- 旧的收藏卡组默认公主塔（tt=159000000）。

### 卡牌筛选与排序

搜索框旁边是**排序**下拉：默认顺序 / 费用 ↑ / 费用 ↓ / 名称 A→Z / 可觉醒优先 / 可精英优先 / 英雄优先。

下面是**筛选标签**（可组合）：

`全部` `部队` `法术` `建筑` `塔防`（五选一）｜ `空中单位` ｜ `攻城` ｜ `后排` ｜ `觉醒` ｜ `精英` ｜ `英雄`

`塔防` 会列出 4 张塔楼部队，点一下即可设为当前卡组的塔；「全部」里也包含这 4 张塔。

> **实测结论**：链接里确实写入了 `tt=<塔 ID>`（如 `tt=159000004`），但**游戏导入时只会复制 8 张卡**——
> 觉醒 / 精英形态与塔防都不会跟着过来（官方交接的已知限制），需要在游戏内手动确认一次。

### 导入现成的卡组

编辑器的「导入已有内容」可以粘贴复制卡组链接 / `deck=…` / 8 个卡牌 ID，自动解析并按合法位置摆好（英雄卡会自动排到第 2 格）。

**老数据兼容**：如果浏览器里已存的卡组把英雄卡放在了非法位置（历史数据），打开页面时会**自动挪到英雄位**并提示，不需要手动改。

## 界面 / 主题

- 右上角 **◐** 按钮循环切换三套主题：**亮色**（默认，白底 + 蓝金）→ **深空**（深蓝 + 金）→ **霓虹**（暗紫 + 青紫光），选择会记住；
- 筛选面板在**所有标签页**都可用，并同时作用于「我的卡组」与「HOT 卡组」；
- 卡片、弹窗、标签页、按钮统一为玻璃质感 + 柔和光晕；窄屏（手机）自动单列排版；
- 有 favicon（内联 SVG）、`theme-color` 随主题同步、键盘 `:focus-visible` 高亮、`prefers-reduced-motion` 降级动画。

## 性能

- 卡片 HTML 有缓存（切页 / 筛选直接复用，改动卡片时自动失效）；
- 长列表**分批渲染**（首批 12 张，其余空闲时增量追加），首屏不卡；
- 列表用**事件委托**（整页只挂一个监听器，不再每张卡一个）；
- 缩略图 `loading="lazy" decoding="async"`，卡片 `content-visibility:auto` 跳过屏外绘制；
- 搜索输入做了防抖。
- 实测（Chrome）：切到 HOT（120 套）JS 用时 **5.1 ms**；点筛选 **6.3 ms**。

## 标签页

页面用六个标签页组织卡组（顺序固定）：
**`1v1`** → **`HOT 1v1`** → **`决斗`** → **`HOT 决斗`** → **`2v2`** → **`HOT 2v2`**。

- `1v1`（我的卡组）是默认页：全新用户显示空态引导，卡片有 查看 / 编辑 / 删除；
- `HOT 1v1`（热门1v1卡组，内置 120 套）：卡片是 **复制**（**没有删除键**）；
- `HOT 决斗`（热门决斗组合，内置 10 组）：**这一页最大的单位是「4 套卡组」**，见下一节；
- 站内复制：`HOT 1v1` 点「复制」→ 弹出「复制到哪里？」选择框，目前只有 **1v1 · 我的卡组** 可用
  （**决斗** 那个按钮还是「开发中」）；2v2 的 HOT 卡组将直接复制到 2v2；
- 自己卡组里的按钮是 **查看 / 编辑 / 删除** —— 自己的卡组再"复制一份"没意义，查看（导入链接）才是有用的动作；
- `决斗` / `2v2` / `HOT 2v2` 目前显示「该功能正在开发中 · Coming Soon」占位。

### HOT 决斗：4 套卡组是一个整体

部落战决斗的规则是**一次带 4 套卡组、4 套之间卡不能重复**，所以这一页的整体不是一套而是一组。

- 数据来自 [RoyaleTracker 的 Clan War 组合榜](https://royaletracker.gg/best-decks/clan-war)（真实对战胜率排序），
  10 组、每组 4 套，**组内卡牌零重复**；
- 代码里是 `META_DUELS`，用 `node scripts/gen-duels.mjs` 抓取并生成。
  脚本会顺便把每套的 8 张卡**重排到合法槽位**（数据源给的顺序不满足本应用的槽位规则），
  并校验「4 套 / 每套 8 张 / 组内不重复 / 卡都在卡池内 / 形态落在合法槽位」——
  校验不过就直接退出，不会把脏数据写进页面；
- 页面上一个组合卡片里排 4 行，每行是「塔防 + 8 张卡 + 卡组名 + 单套胜率」，
  整行可点，点开就是那一套的**导入链接 / 二维码** —— 决斗要往游戏里一套一套导入，
  直接把链接摆出来最省事，所以这里给的是「查看」而不是「复制」；
- 卡组筛选对组合生效：**组合里只要有任意一套命中筛选条件，这一组就留下**。

## 卡牌分类与形态（觉醒 / 精英 / 英雄）

卡牌分两类：

### 1）英雄卡（冠军）= 本身就是英雄，没有其他形态

共 8 张：**弓箭女皇、骷髅帝王、黄金骑士、武僧、小王子、哥布林斯坦、强力矿工、刺客首领**。

- 格子下方固定显示 `♛ 英雄（固有）`，**没有下拉框**（不存在普通/觉醒/精英）；
- **只能放第 2、3 格**：放到其他格会红字警告「英雄卡只能放第 2、3 格」，并且**无法保存**；
- 卡组列表和详情里也会显示这条警告。

### 2）普通卡 = 8 个格子都能放

其中一部分可以变成觉醒 / 精英（取决于该卡本身有没有这两种形态）：

| 形态 | 可变的卡 | 只能放在 | 说明 |
|---|---|---|---|
| ✦ 觉醒 | 42 张（骑士、迫击炮、骷髅军团…） | 第 1、3 格 | 放在觉醒位就是觉醒卡，放别处就是普通卡 |
| ✚ 精英 | 17 张（骑士、冰法师、野蛮人滚筒…） | 第 2、3 格 | 放在精英位就是精英卡，放别处就是普通卡 |
| 普通 | 全部 127 张 | 第 1–8 格 | 默认形态 |

- 下拉框**只列出该卡真正拥有的形态**：例如迫击炮只有「普通 / ✦觉醒」，冰法师只有「普通 / ✚精英」，火球这种没有形态的卡直接显示 `普通卡`（无下拉框）；
- 位置不允许的形态会**置灰并注明原因**，如 `✦觉醒（觉醒只能放在第 1、3 格）`；
- 位置规则摘要实时显示：`位置规则：1 格：觉醒｜2 格：精英/英雄｜3 格：觉醒/精英/英雄｜4-8 格：仅普通`。

> 觉醒 / 精英名单来自 Supercell 官方卡图资源（存在觉醒图 / 英雄形态图的卡）；英雄卡按冠军稀有度识别。

## 设置（⚙）

- 链接参数：`l`（卡组标签，默认 `Royals`）、`tt`（默认 `159000000`）。
- 形态信息开关与三种形态的编码。
- 8 个位置的形态规则表。
- 恢复默认设置 / 恢复示例卡组。

设置面板只保留 **保存设置 / 恢复默认设置 / 清空我的卡组** 三个按钮（进阶项仍在代码里、默认折叠隐藏）。

「清空我的卡组」只清空你自己创建的卡组（1v1 / 2v2），**不影响 HOT 卡组**。

设置与卡组都存在浏览器 localStorage（`cr_decks_v2` / `cr_settings_v1`），旧版数据（`cr_decks_v1`）会自动迁移。

## 账号与云同步

给联盟战队内部用的小型账号系统：**用户名 + 密码**，登录后卡组 / 设置 / 主题保存在云端，
手机和电脑用同一个账号就能看到同一份数据。

- **不登录也完全能用** —— 数据只存在这台设备的浏览器里，功能一个不少；
- **不收集邮箱**，也没有任何邮件发送环节；忘记密码靠注册时展示一次的**恢复码**；
- 打开方式不受限：`file://` 双击、离线、后端没配好，都会自动退回纯本地模式，页面顶部显示「离线」。

### 用户视角的流程

| 场景 | 行为 |
|---|---|
| 第一次注册 | 填用户名（2–20 位，中文/英文/数字/`_`/`-`）+ 密码（≥6 位）→ 立刻登录，并弹出**恢复码**（只显示这一次） |
| 换设备 | 打开同一网址 → 点右上角「登录」→ 输入账号密码 → 自动拉下云端数据 |
| 首次在某设备登录，且本机与云端都有卡组 | 弹窗三选一：**合并**（推荐）/ 用云端覆盖本地 / 用本地覆盖云端。之后不再问 |
| 忘记密码 | 登录框 →「忘记密码」→ 用恢复码设新密码（旧恢复码作废，换发新的） |
| 退出登录 | 只是本机不再同步；云端数据与本机卡组都还在 |
| 删除账号 | 永久删除云端的账号与全部卡组，**本机 localStorage 不动** |

### 同步是怎么做的

- 卡组 id 由客户端生成（16 位 base36），因此「改名」在云端是**更新同一套**，不会变成删旧建新；
- 每次本地改动（增删改卡组 / 保存设置 / 切换主题）都会通知同步模块，**1.2 秒防抖**后整表 PUT；
- 服务端按 **逐条时间戳「后写入者胜」** 合并，不需要版本号也不会互相覆盖；
- 删除用**墓碑**记录（保留 90 天），所以「A 删掉的卡组」不会被 B 的旧数据复活；
- 设置与主题各自带时间戳独立合并，改主题不会把设置冲掉；
- 页面切到后台或关闭前会用 `keepalive` 补推一次，避免防抖窗口里的改动丢失；
- 客户端用服务端返回的 `serverTime` 校正本机时钟偏差（取往返中值），时钟不准也不会永远输。

### 安全边界（够用就好的取舍）

这是给几十人内部用的小工具，不是金融系统。已经做到：

- 密码用 **PBKDF2-SHA256**（默认 30000 次 + 16 字节随机盐 + 服务端 `PASSWORD_PEPPER`）派生后入库，**不存明文**；
- 会话 Cookie 为 `HttpOnly; Secure; SameSite=Lax`，库里只存 `sha256(token + pepper)`，拖库也无法直接冒用登录态；
- 哈希比较走定长比较，避免时间侧信道；登录失败不区分「用户不存在 / 密码错」；
- 注册 / 登录 / 重置都有限流（按 IP 与账号分别计数）。**账号维度的桶键走 sha256，不把用户名明文写进库**；
- **登录限流只统计失败次数**，成功登录会把该账号的失败计数清零 —— 否则队友在几台设备之间来回登录十几次就会被锁住；
- 所有 SQL 都是 prepared statement 绑定参数；所有读写都带 `user_id` 条件，卡组主键是 `(user_id, deck_id)`，跨用户互不可见；
- 请求体流式读取、按字节计数，超过 256 KB 立即断流（不是先读满再判长度）；
- 时间戳和墓碑都 **fail-closed**：非法值一律当 0（永远输），而不是默认成 `now`（那会让畸形客户端覆盖别人的新数据、甚至删掉别人删不掉的东西）；
- 换密码会作废该用户全部旧会话；注销账号会删掉该用户的全部行；登录时顺手清理过期会话。

**响应头**（`_headers`，只作用于静态资源；`/api/*` 的头在 `functions/_lib/store.js` 里单独加）：

| 头 | 作用 |
|---|---|
| `X-Content-Type-Options: nosniff` | 禁止浏览器猜 MIME |
| `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'` | 挡点击劫持 |
| `Referrer-Policy: no-referrer` | 不把本站 URL 泄露给外部 CDN |
| CSP `base-uri / form-action / object-src 'none'` | 挡 `<base>` 注入、表单外发、插件 |
| `Strict-Transport-Security` | 强制 HTTPS |
| `X-Robots-Tag: noindex` + `robots.txt` | 战队内部工具，不被搜索引擎收录（收录只会招来扫描流量） |

CSP **故意不写 `default-src`**：本页是刻意的单文件内联脚本/样式，写完整 CSP 就必须带 `'unsafe-inline'`，那是自欺欺人。上面这几条指令不需要 `unsafe-inline` 就是实打实的。

未匹配的路径会返回 **404 + 一张几 KB 的静态页**（`404.html`）。这不是装饰：Cloudflare Pages 在没有 `404.html` 时会把首页当作兜底返回，扫描器每探测一次就白拿 190 KB。

**有意没做**（如果以后队伍变大再补）：邮箱验证、二次验证、密码强度校验、审计日志。

> PBKDF2 迭代次数的上限来自 Cloudflare Workers 免费版 **单请求 10ms CPU** 的硬限制（超了直接 Error 1102，代码里 catch 不住）。
> 默认取 30000（配合 pepper 强度足够）。`scripts/probe-prod.mjs` 会在真实部署上连打 8 次登录来验证没有撞上限
> （实测 8/8 成功、零 5xx）。升级到 Workers Paid 后可以设环境变量 `PBKDF2_ITERATIONS=210000`，
> 老密码会在下次登录成功时自动重哈希，用户无感。

> **`pages.dev` 上拿不到 WAF / Bot Fight Mode / 速率限制规则** —— 那些是「区域（zone）」级功能，只有绑了自己的域名才有。
> 所以**应用内的限流是唯一防线**。将来噪声变大或者想要国内访问速度，挂一个自己的域名是最直接的解法。

## 部署（Cloudflare Pages）

线上地址：**https://cr-copy-deck.pages.dev**

架构与 `YunhaoFu/night-maid` 一致：**GitHub 仓库 → Cloudflare Pages（Git 集成）→ push 自动部署**。
账号后端用 Pages Functions + D1，同样是零依赖、零运维、零成本，**不依赖任何自建服务器**。

| 项目 | 值 |
|---|---|
| 仓库 | `github.com/YunhaoFu/cr-copy-deck`（public，`main` 分支） |
| Pages 项目 | `cr-copy-deck` |
| Framework preset | None（本项目无框架、零依赖） |
| Build command | `node scripts/build-site.mjs` |
| Build output directory | `dist` |
| D1 绑定 | 变量名 **`CR_DB`**（Production 与 Preview 各配一次） |
| 环境变量（可选） | `PASSWORD_PEPPER`、`SESSION_PEPPER`（各一串长随机值；改 pepper 会让已有密码失效，**别乱改**） |

### 首次启用账号系统（一次性）

```bash
# 1) 登录 wrangler（需要 Node ≥ 22.5，仓库根目录执行）
npx wrangler login

# 2) 建库
npx wrangler d1 create cr-copy-deck-sync     # 把输出里的 database_id 记下

# 3) 建表
npx wrangler d1 execute cr-copy-deck-sync --remote --file=migrations/0001_sync_auth.sql
```

然后在 Cloudflare 控制台：Pages → `cr-copy-deck` → **Settings → Bindings → Add → D1 database**，
变量名填 `CR_DB`，选中 `cr-copy-deck-sync`（Production 和 Preview 都要配）→ **Deployments → Retry deployment**。

没配 D1 时，`/api/*` 一律返回 `503 storage_not_configured`，前端自动切「离线」，页面照常可用 —— 不会白屏。

### 本地命令

```bash
node scripts/validate.mjs      # 159 项零依赖静态校验（自包含 / 数据不变量 / 账号与同步挂点 / 安全加固）
node scripts/build-site.mjs    # 生成 dist/ 下的 5 个文件（index.html + _routes.json + _headers + 404.html + robots.txt）
node scripts/test-api.mjs      # 133 项后端集成测试（用 node:sqlite 顶替 D1，把 functions/ 真跑一遍）
node scripts/dev-server.mjs    # 本地开发服务器：http://localhost:8788（同时提供页面和 /api/*）
```

本地起服务后就能在浏览器里把注册 / 登录 / 跨设备同步完整走一遍（`--db .dev.db` 可让数据落盘，
默认内存库、重启即清空）。注意用 `http://localhost:8788` 而不是 IP —— 纯 IP 的 http 下浏览器会丢弃 Secure Cookie。

还有一个浏览器端到端测试 `scripts/test-e2e.mjs`（线上模式 53 项，真开 Chrome 跑
「注册 → 建卡组 → 换设备登录 → 双向同步 → 删除 → 离线降级」）。
它依赖 `puppeteer-core`，没有放进 `package.json`，需要时自备：

```bash
# 默认跑本地（自己拉一个开发服务器，用内存库，不碰线上数据）
npm i -D puppeteer-core@23 && CHROME_PATH=/usr/bin/google-chrome node scripts/test-e2e.mjs

# 直接跑线上：会用一次性用户名 e2e-xxx 注册，跑完自动注销账号、不留垃圾数据
E2E_BASE=https://cr-copy-deck.pages.dev node scripts/test-e2e.mjs
```

> 万一自动清理失败，可以手动去 D1 里删：
> `npx wrangler d1 execute cr-copy-deck-sync --remote --command "DELETE FROM users WHERE username_lc LIKE 'e2e-%'"`

### 线上健康探测

`scripts/probe-prod.mjs` 专门验证认证链路没有撞上 Workers 免费版的 CPU 上限：

```bash
node scripts/probe-prod.mjs                       # 打线上，默认连登 8 次
node scripts/probe-prod.mjs --base http://localhost:8788/ --times 5
```

它会注册一个 `probe-xxx` 临时账号、间隔 3 秒连续登录、打印每次的状态码与耗时，跑完自动注销。
**出现任何 5xx 就说明 PBKDF2 迭代数超了 10ms CPU 预算**（退出码 1），此时去控制台加
`PBKDF2_ITERATIONS=15000` 再重跑即可。

### 发版流程

1. 改 `index.html`（如更新卡组数据），并把底部版本号 `APP_VERSION` 递进（例：`v8 · 2026-09-14`）；
2. `git commit && git push` → GitHub Action 跑 `validate` + `build` + `test-api`；
3. CI 通过后 Cloudflare Pages 自动构建部署，几十秒后生效；
4. 用户端若仍是旧版：手机浏览器**硬刷新**（或微信里「在浏览器打开」）。

### 回滚

Cloudflare → Workers & Pages → `cr-copy-deck` → **Deployments** → 选中上一个成功部署 → **Rollback**；
代码侧也可 `git revert` 后 push。数据库结构变更请写新的 `migrations/000N_*.sql`，不要改历史迁移文件。

### 注意：不登录时数据仍在浏览器本地

卡组 / 设置 / 主题都存在 localStorage，**按源（协议+主机+端口）隔离**，所以 `file://`、局域网 `http://192.168.x.x:8000`、
`https://cr-copy-deck.pages.dev` 三处数据互不相通；换域名也不会跟着走。
**登录后就不用再关心这个** —— 云端是跨设备、跨源的同一份数据。手动迁移方法：

```js
// 旧地址 Console：
console.log(localStorage.getItem("cr_decks_v2"))   // 复制整段输出
// 新地址 Console（粘贴上一步的输出，然后刷新）：
localStorage.setItem("cr_decks_v2", '<粘贴>')
// 设置与主题：cr_settings_v1 / cr_theme 同理
```

### 上线后自检

```bash
B=https://cr-copy-deck.pages.dev
curl -sS -o /dev/null -w '%{http_code}\n' $B/api/me            # 期望 401 {"ok":false,"error":"unauthorized"}
curl -sS -o /dev/null -w '%{http_code}\n' $B/                  # 期望 200
curl -sS -o /dev/null -w '%{http_code}\n' $B/info.php          # 期望 404（不再是 200 + 190KB 首页）
curl -sS -o /dev/null -w '%{http_code}\n' $B/zzz-not-exist     # 期望 404
curl -sS $B/robots.txt                                          # 期望 Disallow: /
curl -sSI $B/ | grep -iE 'content-security|x-frame|referrer|nosniff|strict-transport'
node scripts/probe-prod.mjs                                     # 期望 8/8 成功、零 5xx
```

真机再确认：注册 → 建卡组 → 换一台设备登录能看到 → 一端删除另一端刷新也消失 →
断网改动能推上去 → 不登录也能正常用。

## 文件与数据

- `index.html` —— 全部前端功能（单文件，无外部依赖；卡牌库与二维码库已内置）
- `functions/api/{auth,me,sync}.js` + `functions/_lib/store.js` —— Pages Functions 后端（零依赖）
- `migrations/0001_sync_auth.sql` —— D1 表结构（users / sessions / decks / user_settings / auth_limits）
- `_routes.json` —— 只把 `/api/*` 交给 Functions，静态资源不触发函数
- `_headers` —— 静态资源的安全响应头（nosniff / 防点击劫持 / CSP 子集 / HSTS / noindex）
- `404.html` —— 未匹配路径的 404 页（替代 Pages 默认「兜底返回首页」的行为）
- `robots.txt` —— 禁止搜索引擎收录
- `scripts/` —— `validate` / `build-site` / `test-api` / `dev-server` / `probe-prod` / `gen-duels`（均零依赖）；
  `test-e2e` 需自备 puppeteer-core
- `META_DUELS`（内置 10 组决斗组合）由 `node scripts/gen-duels.mjs` 抓取生成，改数据重跑那个脚本
- 卡牌库：127 张（含 Minion Giant、Spirit Empress、Ronin 等新卡）
- 卡图：Supercell 官方 CDN（`api-assets.clashroyale.com`，普通 / `cardevolutions` 觉醒 / `cardheroes` 英雄），
  失败时自动回退 RoyaleAPI CDN；精英无官方图
- 二维码：qrcodejs (MIT)

## 已验证项

- 链接格式与官方页面接受的格式一致（HTTP 200），且与手机里复制的真实链接逐字符一致；
- 页面渲染出的二维码可被解码，内容 == 生成的导入链接（含 `slots=`）；
- 静态校验 159 项、后端集成测试 133 项、浏览器端到端测试 53 项（线上），全部通过；
- 端到端覆盖：注册 → 建卡组 → 换设备登录看到同一份 → 改名（云端仍是同一套，不会变两套）→
  主题 / 设置跨设备生效 → 一端删除另一端刷新也消失且不被旧数据复活 → 首次登录弹合并窗 →
  退出后重新登录 → 恢复码重置密码（旧密码失效）→ `file://` 下判离线、不访问后端、功能照常；
- 安全侧覆盖：超长用户名不建限流桶、限流桶键不含用户名明文、chunked 超大 body 被断流、
  缺时间戳的推送不会覆盖新版本、数组形式的卡组 id 被拒、墓碑缺时间戳直接 400、
  成功登录不被限流且清零失败计数、反复失败仍会被拦、登录时清理过期会话、
  D1 故障不会被伪装成「用户名已注册」、非字符串密码被拒；
- 兼容性：未绑定 D1 时 `/api/*` 返回 503，前端自动离线降级，页面功能不受影响。
